# Architecture

This document describes the system that implements [EXPERIMENT_DESIGN.md](EXPERIMENT_DESIGN.md).
Design principle: **the smallest system that can test H1–H6 rigorously.** Every module has to
earn its place. Modules marked *(later)* are deliberately not created until a milestone needs them.

---

## 1. The closed loop

```
            ┌──────────────────────────────────────────────────────────────────┐
            │                                                                  │
            ▼                                                                  │
   ┌────────────────┐   ┌───────────────┐   ┌────────────────┐   ┌───────────┴──────┐
   │ Dataset        │──▶│ Train BC      │──▶│ Evaluate (val) │──▶│ Diagnose          │
   │ (manifest of   │   │ policy        │   │ per-cell,      │   │ per-cell root-    │
   │  episode IDs)  │   │ (sim-free)    │   │ failure labels │   │ cause hypotheses  │
   └────────────────┘   └───────────────┘   └────────────────┘   └─────────┬────────┘
            ▲                                                              │
            │           ┌──────────────────┐   ┌────────────────┐          │
            └───────────│ Generate demos   │◀──│ Acquisition    │◀─────────┘
                        │ (scripted expert │   │ strategy →     │
                        │  in sim)         │   │ q(θ), budget   │
                        └──────────────────┘   └────────────────┘

   Final test evaluation sits OUTSIDE this loop, reads only frozen checkpoints,
   and writes to a path the loop can't read.
```

## 2. Key architectural decisions

| # | Decision | Why | Alternative considered | Trade-off accepted |
|---|----------|-----|------------------------|--------------------|
| AD1 | **Hard boundary between sim and everything else.** Only `fdrl.sim` imports Isaac Lab. Training, diagnosis, acquisition and analysis work on numpy/torch arrays and episode files. | Isaac Sim-backed workflows must launch the Kit app (`AppLauncher`) before importing most `isaaclab.*` modules, and Isaac Lab is Linux/Windows + NVIDIA only (Isaac Sim additionally needs an RTX GPU). Keeping it isolated lets 80% of the code run and be tested on a Mac or CPU node, and makes a second-simulator replication (Exp 7) a matter of writing one adapter. | Write everything as Isaac Lab scripts | One extra interface layer (~150 lines). |
| AD2 | **State-based observations in v1.** | See EXPERIMENT_DESIGN §2. It isolates the data question from perception, and storage is ~100× cheaper. | Vision from day one | Results don't yet speak to vision policies (planned for M9). |
| AD3 | **Our own small BC trainer** (~300 lines of PyTorch), not robomimic's trainer. | Full control over the protocol (fixed gradient steps, identical across strategies), easy to read for learning, fast. The HDF5 data layout stays **robomimic-compatible** so robomimic and Diffusion Policy can be dropped in for Exp 7. | robomimic BC | We own bugs in a small trainer. Mitigated by a sanity check that compares against robomimic BC once (M4). |
| AD4 | **A dataset is a manifest** (immutable list of episode IDs + content hash), not a file copy. Episodes live once in an episode store. | Strategies, rounds and seeds produce many overlapping datasets. Manifests make provenance exact and storage linear. | Copy HDF5 per dataset | Needs an index (Parquet) and a loader that gathers by ID. |
| AD5 | **Episode index in Parquet**, trajectories in sharded HDF5. | Parquet lets analysis query "all failures with μ < 0.2 in round 2 of S5, seed 3" instantly. HDF5 matches the robomimic/Isaac Lab recorder format. | One SQLite DB; LeRobot format | Two formats. A LeRobot exporter can be added later for interoperability. |
| AD6 | **Scripted expert as a state-feedback controller** (its phase is inferred from state, not from an internal timer). | Lets the expert label *any* state, which DAgger (S6) and the ensemble diagnosis need. It also makes the expert robust to perturbations. | Open-loop waypoint script; RL expert | Slightly harder to write. A learned PPO expert is kept as a backup. |
| AD7 | **Config = typed dataclasses + YAML (OmegaConf)**, with every run's resolved config saved. | Simple, diff-able, no magic. Isaac Lab's own `@configclass` is used *inside* `fdrl.sim` only. | Hydra everywhere | Fewer CLI tricks. Sweeps are generated by a small script. |
| AD8 | **Diagnosis and acquisition start as one package** (`fdrl.intel`). | They share per-cell statistics. Splitting them now would just add interfaces nobody uses. | Separate `data_intelligence/` and `acquisition/` | Split later if the package passes ~1,500 lines. |
| AD9 | **Leakage is prevented structurally**, not by convention (§5). | A single accidental use of test data invalidates the study. | "Be careful" | Slight API friction. |

## 3. Repository layout (initial, minimal)

The proposed 19-directory layout was trimmed. The main problems with it: top-level importable
directories without a `src/` layout cause import-path bugs; `data/` and `results/` invite
committing artifacts; `failure_analysis/`, `data_intelligence/` and `acquisition/` were split
before any of them has code.

## 4. Core data contracts

```python
# fdrl/conditions.py
@dataclass(frozen=True)
class Condition:            # one point θ ∈ Θ
    x: float; y: float; yaw: float; mu: float
    def cell(self, grid: CellGrid) -> int: ...

# fdrl/data/schema.py
@dataclass
class EpisodeSummary:       # one Parquet row; written for EVERY episode (demo, val, test)
    episode_id: str         # uuid4; plus deterministic key = hash(split, seed, θ, policy_id)
    split: Literal["calib", "acq", "val", "test"]
    seed: int; condition: Condition; cell: int
    source: Literal["expert", "policy", "dagger"]
    policy_id: str | None   # checkpoint content hash for policy rollouts
    strategy: str | None; round: int | None; pipeline_seed: int | None
    success: bool; failure_label: str | None; failure_flags: list[str]; failure_t: int | None
    length: int; sim_steps_charged: int; accepted: bool  # rejected expert attempts kept, accepted=False
    diag: dict[str, float]  # min EE–cube dist, grasp yaw err at close, max slip, max height, jerk…
    traj_ref: str | None    # shard path + key; full trajectory stored for demos, failures, 10% of successes

# Trajectory arrays (HDF5, robomimic layout data/<demo_id>/{obs/*, actions, states, ...})
#   obs/*: per-key arrays [T, d]; actions [T, 7]; expert_actions [T, 7] (if relabelled)
#   privileged/: cube pose [T,7], contact forces (finger-cube L/R, cube-table) [T,3], θ

@dataclass(frozen=True)
class DatasetManifest:
    name: str; episode_ids: tuple[str, ...]; parent: str | None; sha256: str

@dataclass
class EvalReport:           # produced by evaluate.py
    split: Literal["val", "test"]; policy_id: str; n_per_cell: int
    per_cell: dict[int, CellStats]   # successes, n, failure-type counts, mean diag signals
```

## 5. Leakage guards (AD9)

1. `fdrl.intel.*` functions take `EvalReport` and assert `report.split == "val"`.
2. `evaluate.py --split test` writes only under `runs/<exp>/test/` and requires a
   `--frozen-analysis <git-sha>` argument, which is recorded in the report.
3. `conditions.py` seed streams are disjoint integer ranges. The sampler refuses to give an
   `acq`/`val` sample from a hold-out cell H.
4. `tests/test_leakage.py` asserts (1)–(3) and greps `fdrl/intel` for any reference to `test/` paths.

## 6. Module responsibilities and build order

| Order | Module | Responsibility | Done when… |
|-------|--------|---------------|------------|
| 1 | `conditions` | Θ, cells, H, seed streams, samplers | property tests: disjoint streams, H never sampled for acq/val |
| 2 | `sim/isaaclab_lift` | derived env with per-env θ applied at reset (position/yaw via reset events; μ via physics-material randomization), contact sensors, success predicate | a θ sweep visibly changes the scene; logged θ matches applied θ (read back from sim) |
| 3 | `expert/scripted` | grasp-lift controller using privileged state, μ-aware lift profile | ≥ 95% success in feasible cells (EXPERIMENT_DESIGN §3) |
| 4 | `data/*` | recording, storage, manifests | round-trip test; 1,000 demos write and read back bit-exact |
| 5 | `policy` + `train` | BC MLP, ensemble | trains on Mac CPU on a fixture dataset; loss decreases; seed-determinism on CPU |
| 6 | `failures` + `evaluate` | taxonomy, per-cell reports | taxonomy audit passes (EXPERIMENT_DESIGN §6) |
| 7 | `intel` (S1–S4b incl. S3b, controls, stats) | baselines and heuristics | unit tests on synthetic EvalReports |
| 8 | `loop` | rounds, budget enforcement, cost ledger | one full round runs end-to-end on the cluster |
| 9 | `intel/diagnose` + S5 | diagnosis and proposed strategy | Exp D pilot |
| 10 | `analysis` | statistics and plots | reproduces every plot from `runs/` with one command |

## 7. Reproducibility

- Every run directory contains: the resolved config, git SHA (and a dirty-tree diff if any),
  `pip freeze`, the Isaac Sim/Lab versions, GPU model and driver, all seeds, dataset manifest
  hashes, and metrics JSON.
- Seeds: `pipeline_seed` → derived seeds for D₀ sampling, training init, data order, acquisition
  sampling and eval episodes (via `numpy.random.SeedSequence`).
- **GPU physics is not guaranteed bitwise deterministic** (verify for the pinned PhysX version).
  We therefore treat reproducibility as *statistical*: re-running a configuration must reproduce
  metrics within their CIs. Training on CPU is deterministic, and that is unit-tested.
- Large artifacts never go to git (see `.gitignore`). Durable artifacts go to cluster storage
  plus optional object storage, referenced by manifest hash.
- Experiment tracking: local JSON plus optional Weights & Biases. Before using W&B, check the
  university's data and cloud policy.

## 9. What we reuse vs build

| Component | Decision | Rationale |
|-----------|----------|-----------|
| Physics, robot model, lift scene, IK action term, managers | **Reuse** Isaac Lab | Mature, GPU-parallel, Franka assets included |
| Parameter randomization (pose, friction) | **Reuse** Isaac Lab event terms (`reset_root_state_uniform`-style, physics-material randomization); write thin wrappers for per-env θ control | We need *exact, per-env, logged* θ, not just random ranges |
| Contact sensing | **Reuse** Isaac Lab `ContactSensor` with filtered prims | |
| Scripted expert | **Build**, starting from Isaac Lab's lift state-machine example (verify it exists in the pinned version) | Must be state-feedback and μ-aware (AD6) |
| Demo generation at scale for harder tasks | **Evaluate later** (pick-place, stacking): Isaac Lab Mimic is *deprecated in 3.0* in favour of AutoData; MimicGen's code license is **non-commercial** (research/evaluation only) | Overkill for lift with a scripted expert; licensing matters for the startup path (RESEARCH §7) |
| BC trainer | **Build** small (AD3); **reuse** robomimic / Diffusion Policy for Exp 7 | Protocol control |
| HDF5 layout | **Reuse** robomimic conventions | Interoperability |
| Stats (bootstrap, IQM) | **Reuse** `rliable` + `scipy` | Standard, reviewed |
| Failure taxonomy, diagnosis, acquisition strategies, loop, cost ledger | **Build** | This is the research contribution |
| Influence / TRAK attribution | **Reuse** existing implementations if Exp 3b warrants it | Expensive; not on the v1 critical path |
| Second simulator | **Reuse** ManiSkill3 PickCube (stretch, Exp 7) | Cross-simulator robustness |
